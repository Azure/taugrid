# TauGrid v0.1.3

TauGrid v0.1.3 is a patch release covering safe automatic configuration and
reuse of workspace connections, portal queue visibility, cluster capacity, and
packaging compatibility.

## Highlights

- Treat checked-in `tau/workspace.connection.yaml` as explicit repository and
  platform preconfiguration. The first cluster-backed command can obtain normal
  AKS cluster-user credentials, verify the live contract, and pin local state
  without a TTY.
- Persist the configuration pin independently from the five-minute live
  readiness cache, and let noninteractive commands refresh an unchanged
  connection through the normal read-only workspace and authorization checks.
- Fail closed when the descriptor, trust identity, workspace UID, namespace,
  LocalQueue, or workload service account changes, or when the workspace is not
  Ready.
- Refuse to render a suspended Kubernetes Job without a Kueue LocalQueue.
- Shrink and re-scope the shared `core` module so the CLI and portal link only
  what they actually need.
- Default the portal Jobs board to a cluster-wide Kueue read and enforce
  explicit queue scopes so researchers see the jobs they are authorized to see.
- Make the Stellar Kusto UI stateless and read-only.
- Support both Helm 3 and Helm 4, including `tau cluster install` on Helm 4.
- Release RayJob node capacity shortly after the job completes.
- Enable the eastus2 workspace and align its Stellar identity.
- Add eastus2 CPU autoscaling capacity and fix Dv5 scale-from-zero admission.

## Compatibility

- `tau workspace connection [PATH]` verifies the selected workspace connection
  live by default; `--offline` validates only the checked-in configuration.
- `tau run` discovers the checked-in descriptor automatically.
- Public environment variables keep the `TAU_` prefix.
- Kubernetes metadata and workspace APIs keep the `tau.azure.com` domain.
- Generated local state keeps `.tau` paths and `tau.*` schema identifiers.
- `experiment` and `portal` verbs continue to require the separate
  `taugrid-portal` binary.
- Repositories should pin the Go CLI and Python SDK to the same release tag.

## Install

1. Install the Python SDK from the `v0.1.3` source revision.
2. Download the matching `tau-<os>-<arch>` binary and `SHA256SUMS`.
3. Verify the checksum before installing the binary as `tau`.
4. Put the verified binary on `PATH` and run `tau version --short`.
